All model effects require the actual installed unit/device lease and admitted placement; no raw inference endpoint fallback exists.

## Client API

Authenticate job routes with `Authorization: Bearer <dedicated node token>`.

`POST /v1/music/jobs` returns HTTP202. Request:

```json
{
  "jobId": "histo-yue2-example-unique-id",
  "ownerId": "histo:project:music",
  "style": "Instrumental low strings and felt piano; no vocals, no singing, no choir",
  "sectionTags": ["Intro", "Verse", "Outro"],
  "seed": 18631019,
  "lyricsMode": "empty",
  "scoreAbc": "EXACT OWNER-AUTHORED VALID NATIVE ABC"
}
```

`scoreAbc` is optional. Omit it to ask YuE2 to compose. `lyricsMode` is `empty` or `sections` (default). Required style conditions are enforced. Allowed section tags: Intro, Verse, Chorus, Bridge, Outro, Solo, Instrumental. Keep consumer plan hashes/lineage outside this strict request schema.

- `GET /v1/music/jobs/{jobId}`: retained request digest, state and receipt.
- `POST /v1/music/jobs/{jobId}/cancel`: requests cancellation; an acknowledgement is **not settlement**.
- `GET /v1/music/jobs/{jobId}/artifacts/audio.flac` (also score.abc, receipt.json): authenticated succeeded artifacts.
- `GET /health`: live incarnation and actual installed source-carrier identity.

Same job ID and exact request digest replays without inference; changed request with that ID refuses409. Use a new job ID/version for an edited score. Preserve the original request, score, seed, model/config/source identities, semantic tokens and latents. The immutable decoded artifact SHA is the mix input identity.

## Editable music and actual limits

Native ABC supports tempo, meter, key, section structure, harmony/chords and instrumental melodic voices. Style controls timbre/density/dynamics but does not guarantee them. The instrumental helper moves sounding Vocal notes into Ins; this alone cannot establish no audible voices. Supply exact ABC when meter/key/tempo must be preserved. A real free-composition attempt ignored requested Bb/72/2/4 and returned C/66/4/4; it was rejected, not normalized. An exact-score follow-up preserved Bb/72/2/4 and every input score byte.

Duration is not an exact API control. Nominal bars/tempo are score timing, **not measured audible beat positions**. Actual outputs were149.358667s for nominal150s and116.598667s for nominal116.666667s. Inspect truncation and decoded duration. Phrase/beat sync needs a measured alignment step or explicitly labelled nominal anchors. Do not stretch/loop silently. The consumer may author trims, repeats, recues and crossfades as explicit score/mix decisions.

Cache by exact score/style/seed/model/config/source identity. A music gain/cue edit reuses generated bytes; a score/style edit regenerates only affected music. Narration and visuals are separate dependencies. Final preview mixing should use the existing measured master clock, with explicit automation/ducking and a final speech-intelligibility review. No semantic decisions should be generated by heuristic code.

## Settlement and recovery

One GPU executor serializes load/evict/generation. Normal successful receipts are retained only after the actual executor returns and CUDA synchronization finishes. Native cooperative cancellation reaches planning/semantic/NAR; an already running VAE decode must finish before terminal cancellation/release. No socket close or future.cancel is physical proof.

Actual normal generation/settlement, completed SQLite reopen and same-job replay were exercised. **Active GPU cancellation was not exercised. Abrupt-process crash recovery is not qualified.** Startup refuses retained nonterminal rows rather than reissuing uncertain work. Resolve exact old-incarnation state before restart; never delete rows to make startup succeed. Exclusive file locking prevents two owners opening the same worker state.
